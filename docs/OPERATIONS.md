# תפעול – מסלול מנוהל

כל מה שכאן נכתב לפי מה שמומש בקוד. מה שדורש חשבון ענן אמיתי מסומן **(לא נבדק בענן)**.

## הפרדה בין עסקים
- כל עסק הוא שורה ב-`businesses`; כל הטבלאות נושאות `business_id`, ו-RLS + פונקציות RPC מבטיחות שבעלים רואה רק את עסקו (נבדק גם בקריאות ישירות עם JWT של בעלים אחר ב-`test/security.test.mjs`).
- Super Admin: MFA (aal2) נאכף ב-DB; פעולות רגישות (הקמה, מחיקה, איפוס סיסמת בעלים, אישור מחירים, הקפאה) דורשות אימות TOTP טרי (15 דקות).
- עסקי הדגמה (`demo-*`) מופרדים: ללא בעלים וללא דומיין (נאכף ב-DB), נתוניהם נמחקים בתחזוקה השעתית אחרי יום.

## ניטור
- `GET /api/health` – מחזיר `{"ok":true}` רק אם האתר והמסד עונים (503 אחרת). מכוונים אליו כל כלי ניטור חיצוני (למשל בדיקת uptime) **(לא נבדק בענן)**.
- `GET /api/admin/system` (למנהל מחובר) – מצב מסד, ספק הודעות (כבוי עד חיבור), הגבלת קצב.
- יומן פעולות (`audit_log`, ללא נתונים אישיים, נשמר 400 יום): הקמה/מחיקה/שיוך בעלים/איפוס/הקפאה/שינוי מותג/הדגמות.
- תחזוקה שעתית: Netlify Scheduled Function `maintenance` – מנקה מוני קצב, יומן ישן, ונתוני הדגמה. יש לוודא בלוח Netlify שהיא רצה **(לא נבדק בענן)**.

## גיבוי
- גיבוי המסד עצמו: באחריות הגדרות Supabase (גיבויים יומיים / PITR תלויים בתוכנית הפרויקט). **יש לאמת בלוח Supabase מה פעיל בפרויקט שלכם** – לא ניתן לבדוק מכאן.
- גיבוי לוגי לכל עסק בנפרד: `SUPABASE_URL=… SUPABASE_SERVICE_ROLE_KEY=… node scripts/backup-businesses.mjs <dir>` – קובץ JSON לעסק (הרשאות 600), פורמט זהה לייצוא ההגירה ולכן ניתן לשחזור בייבוא (`rpc_admin_import_business_frozen`). הקבצים כוללים נתוני לקוחות: הצפנה, גישה מוגבלת, מחוץ לגיט.
- מומלץ לבדוק שחזור תקופתית לפרויקט staging: ייבוא + `rpc_admin_business_fingerprint` אל מול המקור.

## פעולות שוטפות
| צורך | איך |
|---|---|
| עסק חדש | פלטפורמה ← "+ עסק חדש" (אשף) |
| השבתת עסק | פלטפורמה ← "השבתה" (מנתק בעלים; נתונים נשמרים) |
| הקפאת כתיבה (תחזוקה/הגירה) | פלטפורמה ← "הקפאת כתיבה"; לקוחות רואים "בתחזוקה זמנית" |
| החלפת סיסמת בעלים / בעלים נוסף | "בעלי העסק" בכרטיס העסק |
| דומיין מותאם | הגדרות העסק ← "דומיין מותאם" (TXT + CNAME, בדיקת חיבור) + Domain alias ב-Netlify |
| עדכון מחירי האתר | לשונית "מותג" (שמירה = טיוטה; אישור דורש TOTP טרי) |
| לידים מהאתר | לשונית "מותג" ← "פניות מהאתר" (נפרד מפניות העסקים) |

## רוטציית סודות
- `SUPABASE_SERVICE_ROLE_KEY`, `ANON_KEY`: מחליפים ב-Supabase ומעדכנים משתני סביבה ב-Netlify ופורסים מחדש.
- `RATE_LIMIT_PEPPER`: משפיע על hash של IP/טלפון להגבלת קצב ועל חותמת בדיקת הדומיין בלבד. **אינו שובר קישורים אישיים של לקוחות** (נבדק). אחרי החלפה, מוני קצב מתאפסים.
- אחרי העברה ללקוח (מסלול חד-פעמי): מפתחות חדשים שנוצרו בחשבונו; מסירים את הגישה שלנו (ראו HANDOVER.md).
